## Task 1: `project create` und `sprint create` ohne Pflicht-Titel

**Ziel:** `-t/--title` ist bei `backe project create <pfad>` und `backe sprint create <slug>` optional. Fehlt es, gilt als Titel bei Projekten das **letzte Pfadsegment** (`web/auth` → `auth`, `web` → `web`), bei Sprints der **Slug**. `issue create` behält `-t` als Pflicht.

**Entscheidung (Ruling):** Der Default entsteht im Service-Layer (`createProject`, `createSprint`), nicht im CLI. Die aufgezeichnete Operation (`project.create`, `sprint.create`) trägt immer einen expliziten `title`; das Operations-Schema in `src/ops/operation.ts` und das Batch-Format (§2.16.6) bleiben unverändert.

**Dateien:**
- `src/services/projects.ts` — `createProject`: `title` im Input optional; fehlt er, letztes Segment von `path`.
- `src/services/sprints.ts` — `createSprint`: `title` optional; fehlt er, `slug`.
- `src/cli/commands/project.ts` — `create`: `.requiredOption('-t, --title …')` → `.option('-t, --title <titel>', 'Titel (Default: letztes Pfadsegment)')`; `title` nur weiterreichen, wenn gesetzt.
- `src/cli/commands/sprint.ts` — `create` analog, Hilfetext `'Titel (Default: Slug)'`.
- Tests: `src/services/projects.test.ts`, `src/services/sprints.test.ts` — je ein Test für den Default (Projekt: `web` und Unterprojekt `web/auth` → Titel `auth`; Sprint: Slug als Titel) und dass ein explizites `-t` unverändert gilt. Falls es e2e-/CLI-Tests für `project create`/`sprint create` gibt (`grep -rn "project create\|sprint create" test src`), dort einen Aufruf ohne `-t` ergänzen.
- `docs/proposals/backe.md` — §2.9: Frontmatter-Satz ergänzen: »`title` ist beim Anlegen optional; ohne Angabe gilt das letzte Pfadsegment.« §2.10: »`title` ist beim Anlegen optional; ohne Angabe gilt der Slug.«

**Akzeptanz:**
- `backe project create web` legt `projects/web.md` mit `title: web` an; `backe project create web/auth` mit `title: auth`.
- `backe sprint create 2026-w48` legt `title: 2026-w48` an.
- Mit `-t "X"` gilt `X` wie bisher.
- `pnpm lint` und `pnpm test` grün.

**Commit:** `feat(cli): project create und sprint create ohne Pflicht-Titel`

## Task 2: `issue edit --help` nennt den Editor-Modus

**Ziel:** Der Editor-Modus ist gebaut (`src/cli/commands/issue.ts`, `editInEditor`; Spec `backe.md` §2.17 »`issue edit` per Editor«), aber `backe issue edit --help` erwähnt ihn nicht. Die Hilfe soll ihn nennen.

**Dateien:**
- `src/cli/commands/issue.ts` — am `edit`-Subcommand per commander `addHelpText('after', …)` einen Block anhängen. Inhalt (sinngemäß, deutsch, kurz):
  ```
  Ohne Änderungs-Flags öffnet `backe issue edit <id>` die Issue-Datei (Frontmatter und
  Body) im Editor. Editor: BACKE_EDITOR, sonst VISUAL, dann EDITOR — die beiden letzten
  nur, wenn stdin und stdout ein Terminal sind.
  ```
  Die Beschreibung des Subcommands darf zusätzlich »… oder im Editor« tragen, wenn das zum Stil der übrigen Beschreibungen passt.
- Test: einen Test, der die Hilfeausgabe von `issue edit --help` auf den Editor-Hinweis prüft (Vorbild: wie `test/e2e/core.test.ts` `--help` aufruft; oder ein Unit-Test über `buildProgram` aus `src/cli/run.ts`, falls das im Repo üblich ist).
- Spec: keine Änderung nötig — §2.17 beschreibt den Modus bereits.

**Akzeptanz:**
- `backe issue edit --help` zeigt den Block mit `BACKE_EDITOR`, `VISUAL`, `EDITOR`.
- Verhalten von `issue edit` unverändert.
- `pnpm lint` und `pnpm test` grün.

**Commit:** `docs(cli): issue edit --help nennt den Editor-Modus`

## Task 3: Schnellstart in `backe --help`

**Ziel:** `backe --help` (und `backe help`) endet mit einem deutschen Abschnitt »Schnellstart«, damit ein neuer User weiß, womit er anfängt. Nur auf dem Root-Programm, nicht in den Unterbefehlen.

**Dateien:**
- `src/cli/run.ts` — in `buildProgram` am Root-`program` per `addHelpText('after', …)`. Inhalt orientiert sich am Quickstart im `README.md` (Abschnitt »Quickstart«), etwa 10–14 Zeilen, Befehle exakt so, wie das CLI sie kennt:
  ```
  Schnellstart:
    backe config set user <handle>          eigenes Handle setzen
    backe init <verz> --name <n> --prefix <p> --remote <url>
                                            neues Backlog anlegen (oder: backe backlog clone <url>)
    backe project create web                Projekt anlegen (-t für einen Titel)
    backe sprint create 2026-w48            Sprint anlegen
    backe new -t "…" -p web -s 2026-w48     Issue anlegen
    backe ls                                offene Issues
    backe show <id>                         Issue anzeigen
    backe mv <id> in_progress               State ändern
    backe next --claim                      nächstes Issue holen und übernehmen (Agents)
  Mehr: backe <befehl> --help
  ```
  Jede Zeile gegen das tatsächliche CLI prüfen (`node dist/cli.js <befehl> --help`), insbesondere `backlog clone`, `init`-Flags und `config set user`. Nichts aufnehmen, was es nicht gibt. Setzt Task 1 voraus (`project create` ohne `-t`).
- Test: `test/e2e/core.test.ts` (der bestehende `--help`-Test) um eine Prüfung auf »Schnellstart« erweitern; zusätzlich prüfen, dass `backe issue --help` den Block **nicht** enthält.
- Spec: `docs/proposals/backe.md` §2.17 nach dem Befehlsblock einen Satz: »`backe --help` endet mit einem Abschnitt ›Schnellstart‹, der die ersten Befehle für ein neues Backlog zeigt.«

**Akzeptanz:**
- `backe --help` endet mit dem Schnellstart; Unterbefehls-Hilfen nicht.
- Alle gezeigten Befehle existieren mit den gezeigten Flags.
- `pnpm lint` und `pnpm test` grün.

**Commit:** `feat(cli): Schnellstart in backe --help`
