# backe M7 — MCP-Modus Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `backe mcp` nach backe.md §2.19: MCP-Server über stdio mit den Tools und der Resource aus §2.19, `--allow-delete`, periodischem Hintergrund-Sync und Start nur mit auflösbarer Identität samt Key. Dazu der mit `M7` markierte offene Punkt aus M6 und die Festlegung »Hints mit CLI-Flags in `ops`/`context`« (M5a).

**Architecture:** `src/mcp/` ist ein zweiter, dünner Adapter über denselben Service-Layer wie die CLI (backe.md §3.7). Damit beide Türen dieselben JSON-Ergebnisse liefern, wandern die JSON-Ansichten, die heute in `src/cli/` gebaut werden, in ein reines Modul `src/services/views.ts`; die CLI ruft sie auf, ihre Golden-Files bleiben byte-gleich. Jeder Tool-Aufruf löst den Kontext neu auf (wie jeder CLI-Aufruf), lokale Writes laufen im Server nacheinander, Claim und `sync_now` daneben. Den Hintergrund-Sync startet der Server genauso wie die CLI über `scheduleSync` — nach Writes mit Commit, vor lesenden Tools und periodisch per Timer alle `pull_interval` Sekunden. Gestartet wird über `serveStdio` des SDK v2, das je Verbindung die Protokoll-Generation aushandelt und dafür die Server-Factory unter Umständen zweimal aufruft; die Factory baut deshalb nur ein `McpServer` mit registrierten Tools, Warteschlange und Timer leben einmal je Prozess daneben.

**Tech Stack:** wie M6, dazu MCP-SDK v2: Runtime `@modelcontextprotocol/server` `^2.4.0` (zieht `@modelcontextprotocol/core` transitiv, braucht `zod ^4.2.0`, passt zu `zod ^4.6.7`), Dev `@modelcontextprotocol/client` `^2.4.0` für die Tests. Tool-Schemas als `z.object(…)` (Standard Schema); rohe Shapes sind in v2 deprecated.

**Spec:** `docs/proposals/backe.md` (§2.14, §2.16.1–2.16.3, §2.16.5, §2.16.6, §2.17–2.19, §2.22, §2.24, §3.7, §5), Gesamtplan `docs/superpowers/plans/2026-11-18-backe-gesamtplan.md`. Es gelten dessen Global Constraints, die M7-Zeile in »Übernommen aus M6« und die Planentscheidungen.

## Global Constraints

Alle Global Constraints des Gesamtplans und von M5a–M6 (Schichten, Services als Eingabegrenze, Fehlercodes, Meldungen mit `»…«`, JSON eine Zeile mit snake_case-Keys, kein Env-Schalter im ausgelieferten Code, Tests ohne Netz und ohne Timing). Dazu für M7:

- **stdout gehört dem Protokoll.** Im MCP-Modus schreibt nur der `StdioServerTransport` nach stdout. Kein `console.log`, kein `process.stdout` in `src/mcp/**`, `src/git/**`, `src/ops/**`, `src/store/**`, `src/context/**`, `src/core/**` überhaupt; Kindprozesse laufen mit `stdio: 'pipe'` oder ins Log (Bestand: `src/git/exec.ts`, `src/services/schedule.ts`).
- **Eine Tür, ein Ergebnis.** Ein MCP-Tool liefert dasselbe JSON-Objekt wie der entsprechende CLI-Befehl mit `--format json` (gleiche Keys, gleiche Auslassungen), gebaut von derselben Funktion in `src/services/views.ts`. Ausnahmen stehen in den Festlegungen.
- **Ein Aufruf, eine Operation** (backe.md §2.16.4): Jedes schreibende Tool ruft genau einen Service, der genau eine Operation (bzw. `batch` einen Batch) schreibt.
- `src/mcp/**` importiert nichts aus `src/cli/**` und umgekehrt (außer `src/cli/commands/mcp.ts` → `src/mcp/stdio.ts`).
- Coverage-Gate neu: `'src/mcp/**': { lines: 90, branches: 85 }`; die Tests laufen in-process über den In-Memory-Transport und zählen.
- Tool-Beschreibungen und Meldungen deutsch wie die CLI; Parameternamen snake_case wie die JSON-Keys (§2.18).

## Review Focus

1. **Fremde Bytes auf stdout** — Irgendeine Schicht schreibt eine Zeile nach stdout (Debug-Ausgabe, Warnung, ein Kindprozess mit geerbtem stdio). Erwartet: kann nicht passieren; der Client sieht nur JSON-RPC. → Task 6 `stdout carries only JSON-RPC over a full flow` (E2E über echten stdio) und Task 2 `no layer below the adapters writes to stdout` (Konventionstest).
2. **Parallele Tool-Aufrufe** — Ein Client schickt fünf `comment_add` gleichzeitig, oder einen Write, während `sync_now` läuft. Erwartet: alle gelingen, fünf Commits, kein `conflict` aus dem eigenen Write-Lock. → Task 4 `concurrent writes from one client all land`, Task 5 `a write during sync_now lands`.
3. **Ungültige oder widersprüchliche Parameter** — leere Strings, `issue_rank` mit `top` und `before`, `issue_update` ohne Änderung, `props` mit einem Key, den §2.24 verbietet, eine mehrdeutige Kurz-ID. Erwartet: Tool-Ergebnis mit `isError: true` und `{"error":{"code":"usage"|"validation",…}}`, der Server läuft weiter, der nächste Aufruf gelingt. → Task 4 `contradictory parameters are usage errors and the server keeps serving`.
4. **Unerwarteter Fehler in einem Service** — ein roher Node-Fehler statt `BackeError`. Erwartet: `isError: true`, Code `unexpected`, Meldung ohne Stacktrace, Server läuft weiter. → Task 2 `an unexpected error becomes an error result without a stack`.
5. **Start ohne Identität oder mit fremder Arbeitskopie** — kein Handle, kein Key, `--as` eines Users ohne Eintrag in `identities`, `-B` auf die Arbeitskopie eines anderen Handles. Erwartet: Der Server startet nicht, stderr trägt `Fehler: …` und `Hinweis: …` wie die CLI, Exit 2, stdout bleibt leer. → Task 6 `mcp refuses to start without an identity`, Task 2 `prepareMcp rejects a foreign working copy`.
