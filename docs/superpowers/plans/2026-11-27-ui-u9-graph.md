# backe ui U9 — Abhängigkeitsgraph Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Der Tab Issue zeigt den Abschnitt »Abhängigkeiten« (einklappbar) mit einem geschichteten Graphen — Voraussetzungen oben, das Issue hervorgehoben in der Mitte, Abhängige darunter, Tiefe 2, je Knoten aufklappbar, Sammelknoten über 150 — und derselben Nachbarschaft als Baum; beides rechnet live auf dem Store und lädt als eigener Chunk erst, wenn der Abschnitt sichtbar wird.

**Architecture:** Drei Schichten wie U8. Unten rein: BK bekommt in `src/ops/graph.ts` die Gegenrichtung von `blocked_by` (`blocking`), der Client rechnet in `web/src/app/dep-graph.ts` daraus und aus `graphOf` die gezeigte Nachbarschaft (Knoten, Kanten, Sammelknoten) und den Baum — keine eigenen Gegenrichtungen im Client. Darüber im Lazy-Chunk `web/src/components/deps/`: `dep-layout.ts` (dagre, rein), `DepGraph.tsx` (`@xyflow/react`), `DepTree.tsx`, `DepPanel.tsx`. Oben die Hülle `DependencySection.tsx` im Hauptchunk: Sichtbarkeit, Klappzustand, Umschalter, `React.lazy` hinter `IntersectionObserver`.

**Tech Stack:** wie U8. Neu als `devDependency`: `@dagrejs/dagre@3.1.4` (Task 2) und `@xyflow/react@13.0.3` (Task 3), jeweils `pnpm add -D <paket>@<version>`, Version in die Commit-Message.

**Spec:** `docs/proposals/ui.md` §2.9.5, §3.8, dazu §2.5 »Ansichtszustand«, §2.13 (Zustände über Icon und Text, Zugänglichkeit), §2.16 »Code-Splitting«. BK `docs/proposals/backe.md` §2.22, §2.23. Gesamtplan `docs/superpowers/plans/2026-11-26-ui-gesamtplan.md` (U9). ui.md ist `in Umsetzung`.

## Global Constraints

Alle Global Constraints des Gesamtplans und der Pläne U1–U8. Dazu für U9:

- Graph-Beziehungen nur aus `@backe/ops/graph.ts` (`graphOf`, `blocking`) und den Feldern der Issues im Snapshot von `store.toSnapshot()`; keine zweite Gegenrichtung im Client.
- Kantenrichtung: von der Voraussetzung zum Abhängigen. `depends_on` durchgezogen, `blocked_by` gestrichelt, `parent` (nur mit »Parent-Kanten zeigen«) gepunktet, vom Sub-Issue zum Parent.
- Default-Tiefe 2 in jede Richtung (`DEP_DEPTH = 2`); Sammelknoten, sobald die Nachbarschaft mehr als 150 Knoten hätte (`DEP_NODE_LIMIT = 150`): 150 Knoten plus ein Sammelknoten mit dem Rest; dieselbe Grenze für die Zeilen des Baums.
- Knoten zeigen ID, gekürzten Titel und State-Icon samt State-Namen; erledigte (`isSettled`) abgeschwächt über gestrichelten Rand und Titel in `text-muted-foreground` (kein `opacity`, Kontrast WCAG AA nach ui.md §2.13), offene Voraussetzungen mit `border-2 border-foreground` und einem Text für Screenreader; das Issue selbst hervorgehoben und kein Link.
- Klick auf einen Knoten öffnet seinen Issue-Tab (`routeHref` + `useLinkClick`); fehlende IDs und der Sammelknoten sind keine Links.
- Ansichtszustand (offen, Graph/Baum, Parent-Kanten) je Backlog im `localStorage` über `lib/storage.ts`, Key `backe-ui:<backlog>:deps`, fehlertolerant; Aufklappen einzelner Knoten ist flüchtig je Tab.
- Neue Texte en + de in `web/src/views/deps.messages.ts`. Feldnamen `depends_on`, `blocked_by`, `parent`, State-Namen und IDs bleiben roh.
- Initialer Chunk ≤ 300 KB gzip (`scripts/check-ui-build.ts`): `@xyflow/react`, `@dagrejs/dagre`, ihre CSS und `components/deps/**` nur im Lazy-Chunk.
- Nur lesen: Der Abschnitt schreibt nichts; er sieht mit und ohne Schreibrecht gleich aus.

## Review Focus

1. **Zyklen** — `blocked_by` im Kreis (`a` blockiert `b`, `b` blockiert `a`) oder ein Hand-Edit mit Zyklus in `depends_on`. Erwartet: Graph endet, jeder Knoten einmal; der Baum markiert die Wiederkehr als »Zyklus« ohne Kinder. → Task 1 `a cycle ends and every node appears once`, `the tree marks a cycle and stops there`.
2. **Verweis ins Leere** — `depends_on: ['bk-gone']` ohne Issue. Erwartet: Knoten »fehlt«, zählt als offene Voraussetzung, kein Link, nicht aufklappbar, keine Ausnahme. → Task 1 `a missing prerequisite is a node without issue`, Task 3 `a missing node is no link`.
3. **Große Nachbarschaft** — ein Issue mit 400 Abhängigen. Erwartet: 150 Knoten plus Sammelknoten »+251 weitere Issues«, Layout ohne Hänger, Aufklappen gesperrt, solange abgeschnitten ist. → Task 1 `over 150 nodes a collector takes the rest`, Task 2 `150 nodes and the collector lay out without overlap`, Task 3 `the collector shows the rest and no node expands`.
4. **Patch bei offenem Abschnitt** — Titel eines Knotens ändert sich; eine Kante verschwindet; die letzte Kante des Issues verschwindet. Erwartet: Titel live ohne neues Layout (gleicher `key`), Knoten verschwindet, Abschnitt verschwindet. → Task 1 `the key stays when only fields change`, Task 5 `the section follows patches live`.
5. **Aufgeklappter Knoten verschwindet** — ein Patch löscht ein aufgeklapptes Issue oder nimmt seine Kante weg. Erwartet: der Eintrag in `expanded` wirkt nicht mehr, keine Ausnahme, seine Nachbarn fallen weg. → Task 1 `an expanded node that left the graph expands nothing`.

```ts
// src/ops/graph.ts
/** Issues, die per `blocked_by` an der Schlüssel-ID hängen, nach `compareIssues`; einmal je Snapshot (WeakMap auf `s.issues`). */
export function blocking(s: BacklogSnapshot): ReadonlyMap<string, readonly string[]>;

// web/src/app/dep-graph.ts
export const DEP_DEPTH = 2;
export const DEP_NODE_LIMIT = 150;
export type DepEdgeKind = 'depends_on' | 'blocked_by' | 'parent';
/** Kante von der Voraussetzung `from` zum Abhängigen `to`; `parent` vom Sub-Issue zum Parent. */
export type DepEdge = { from: string; to: string; kind: DepEdgeKind };
export type DepNeighbour = { id: string; kind: DepEdgeKind };
/** `depends_on`, dann `blocked_by` (Feldreihenfolge), mit `parents` die Sub-Issues (`graphOf.children`); fehlende IDs inbegriffen. */
export function prerequisitesOf(s: BacklogSnapshot, id: string, parents: boolean): DepNeighbour[];
/** `graphOf.dependents`, dann `blocking`, mit `parents` der Parent (falls vorhanden). */
export function dependentsOf(s: BacklogSnapshot, id: string, parents: boolean): DepNeighbour[];
/** Zeigt der Tab den Abschnitt: eine Kante in `depends_on`, `blocked_by` oder Gegenrichtung; `parent` zählt nicht. */
export function hasDependencies(s: BacklogSnapshot, id: string): boolean;
export type DepRole = 'center' | 'up' | 'down' | 'side';
export type DepNode = {
  id: string;
  /** `undefined`: die ID steht in einer Kante, das Issue fehlt. */
  issue: Issue | undefined;
  role: DepRole;
  /** offene Voraussetzung: `role === 'up'` und fehlend oder nicht erledigt. */
  open: boolean;
  /** Nachbarn (beide Richtungen), die nicht gezeigt werden. */
  hidden: number;
  expanded: boolean;
};
export type DepGraph = {
  nodes: DepNode[];
  edges: DepEdge[];
  /** Knoten im Sammelknoten; 0 ohne. */
  more: number;
  /** Knoten-IDs und Kanten; ändert sich nur mit der Struktur, nicht mit Titeln oder States. */
  key: string;
};
export function depGraph(
  s: BacklogSnapshot,
  id: string,
  opts: { parents: boolean; expanded: ReadonlySet<string>; limit?: number },
): DepGraph;
export type DepTreeItem = {
  /** Pfad ab der Mitte, je Segment mit Art: `up:<id>~<kind>/<id>~<kind>` bzw. `down:…`; Schlüssel für `toggled`, eindeutig auch unter Geschwistern, die dieselbe ID über zwei Arten nennen. */
  key: string;
  id: string;
  issue: Issue | undefined;
  kind: DepEdgeKind;
  /** Die ID steht schon weiter oben im Pfad (oder ist die Mitte): keine Kinder. */
  cycle: boolean;
  /** Hat Nachbarn in seiner Richtung, ist kein Zyklus und nicht fehlend. */
  expandable: boolean;
  open: boolean;
  children: DepTreeItem[];
};
export type DepTree = { up: DepTreeItem[]; down: DepTreeItem[]; more: number };
export function depTree(
  s: BacklogSnapshot,
  id: string,
  opts: { parents: boolean; toggled: ReadonlySet<string>; limit?: number },
): DepTree;
```

Regeln `depGraph`:
- Reihenfolge der Knoten: Mitte; dann je Ebene `d = 1 … DEP_DEPTH` erst die Voraussetzungen (Rolle `up`, nur weiter nach oben), dann die Abhängigen (Rolle `down`, nur weiter nach unten) der Knoten der Ebene davor; Nachbarn eines Knotens in der Reihenfolge von `prerequisitesOf`/`dependentsOf`; schon gezeigte IDs nicht erneut; fehlende Issues laufen nicht weiter.
- Danach Aufklappen: Die Liste wird von vorn durchlaufen; jeder Knoten in `expanded` (außer der Mitte, außer fehlende) hängt seine noch nicht gezeigten Voraussetzungen, dann Abhängigen an. Rolle des neuen Knotens: Voraussetzung eines `up` → `up`, Abhängiger eines `down` → `down`, sonst `side`. Neu Angehängtes wird beim selben Durchlauf selbst aufgeklappt, wenn es in `expanded` steht. Einträge in `expanded`, die nicht in der Liste landen, wirken nicht.
- Mehr als `limit` (Default `DEP_NODE_LIMIT`) Knoten: die ersten `limit` bleiben, `more` = Rest. `edges` = jede Kante `prerequisitesOf(x)` → `x` zwischen gebliebenen Knoten, je Paar und Art einmal. `hidden` zählt Nachbarn beider Richtungen außerhalb der gebliebenen Knoten (fehlende Issues: 0). `expanded` am Knoten = in `opts.expanded` und nicht die Mitte.
- `key` = Knoten-IDs mit `role` und Kanten als ein String, dazu `more`.

Regeln `depTree`: `up` sind die Voraussetzungen der Mitte, darunter jeweils deren Voraussetzungen; `down` entsprechend die Abhängigen. Offen per Default auf Ebene `< DEP_DEPTH` (Ebene 1 zeigt Ebene 2, Ebene 2 ist zu); `toggled` kehrt den Default je `key` um. Zyklus: ID im eigenen Pfad samt Mitte → `cycle: true`, `expandable: false`, keine Kinder. Zählung in Vorordnung über `up`, dann `down`; nach `limit` Zeilen entsteht keine weitere, jede ausgelassene Zeile zählt in `more` einmal (ihr Teilbaum nicht).

## Festlegungen

| Stelle | Festlegung |
| --- | --- |
| Gegenrichtung von `blocked_by` | ui.md §2.9.5 nennt `dependents` als Gegenrichtung; BK kennt sie nur für `depends_on`. Ein Issue, das andere blockiert, ist für diese ebenso Voraussetzung. `blocking` steht in `graph.ts`, damit der Client keine eigene Gegenrichtung rechnet; `issue show` bleibt unverändert. |
| Richtung der Parent-Kanten | Ein Parent lässt sich mit offenen Sub-Issues nicht abschließen (BK §2.23); die Sub-Issues sind seine Voraussetzungen. Parent-Kanten zeigen darum vom Sub-Issue zum Parent, Sub-Issues stehen oben — derselbe Pfeilsinn wie bei `depends_on`. |
| Aufklappen | Ein Knoten klappt seine direkten Nachbarn in beide Richtungen auf; die Default-Tiefe 2 gilt nur ab der Mitte. Rolle `side` für Nachbarn quer zur Richtung, offene Voraussetzung nur bei Rolle `up`. |
| Sammelknoten | 150 Knoten in Breitensuche-Reihenfolge bleiben, der Rest steht im Sammelknoten; solange er da ist, klappt kein Knoten auf (es käme nichts hinzu). Weiter geht es über den Tab des Nachbarn. Der Baum hat dieselbe Grenze in Zeilen. |
| Fehlende Issues | Eine ID in `depends_on`/`blocked_by` ohne Issue ist ein Knoten »fehlt«, zählt wie in `readiness` als nicht erledigt, ist kein Link und klappt nicht auf. |
| Baum | Eigener Klappzustand je Pfad, Default offen bis Ebene 2; Zyklen erscheinen einmal mit Marke, nicht endlos. Verschachtelte Listen mit Links und Klappknöpfen statt `role="tree"` — Tab-Reihenfolge genügt, keine eigene Pfeiltasten-Logik. |
| Zoom | `zoomOnScroll` aus, damit das Mausrad im Tab die Seite scrollt; Zoomen über Strg + Rad, Pinch und die Knöpfe der `Controls`; passt der Graph nur unter Zoom 0,75 ein, steht die Mitte bei 0,75 im Bild. |
| Lazy-Chunk | `DepPanel` samt `@xyflow/react`, `dagre` und deren CSS lädt per `React.lazy`, erst wenn der offene Abschnitt sichtbar ist; die Hülle prüft `hasDependencies` im Hauptchunk, ohne die Bibliotheken. |
| Ort im Tab | Nach den Anhängen, vor der Zeitleiste, wie in `issue-details.png`; die Zeitleiste wächst unbegrenzt und gehört ans Ende. |
